# 设计决策记录

本文件记录**为什么这样设计**，不重复 README 里的运行方法与结果。所有取舍都服务于一个目标：让"改进"成为一个能被数据检验的条件，而不是一句自我评价。

---

## 1. 为什么是这两个实验

课程要求从 W5–W8 里选 2–3 个经典范式。选 Stroop（W6）与 Cleveland–McGill 比例判断（W7）有三个理由：

1. **两类测量互补**：一个是反应时（速度—准确性权衡），一个是判断误差（无时间压力）。两套数据放在一起，能说明"注意与显示设计"不只影响快慢，也影响读数的准确。
2. **改进都能落到具体条件上**：Stroop 可以操纵"颜色与词是否属于同一客体"；比例判断可以操纵"有没有共同刻度"。两者都能在网页里精确实现，不依赖特殊硬件。
3. **可控的试次量**：一个人两个实验共约 12 分钟，n=5 的招募压力可接受；每个条件仍有 10–20 个试次。

没有选变化盲/非注意盲，是因为这类范式通常需要大样本才能稳定估计"看见率"，5 个人做不出可解释的效应量。

---

## 2. 改进一：为什么是"显示分离"，不是"一致性比例"

最初考虑过操纵一致性比例（50% vs 20% congruent）来检验情境性控制调整。放弃的原因：

- 比例一致性效应通常只有 10–30 ms，n=5 时交互检验的功效极低，很可能得到一个无法解释的零结果；
- 它需要更多试次才能让被试"学到"比例（每块至少 40–60 试次），会挤占时长预算。

显示分离的预期效应更大、更直观，而且直接对应工程心理学关心的"显示编码"问题：颜色与词义被整合进同一个客体，还是分成两个客体？分离之后干扰若下降，说明整体编码是干扰的重要来源；若干扰仍在，说明语义冲突可以跨空间起作用。

**必须承认的混淆**：分离条件同时改变了"词的颜色"（彩色 → 中性灰）与"注意对象"（字 → 色块）。因此干扰下降不能单独归因于"去整合"，也可能来自词变得不显眼、注意被色块吸走。要真正分离这两种解释，需要"灰色词 + 无冲突色块"的对照条件——本实验没有做，写进局限。

---

## 3. 改进二：为什么是"刻度"，不是"数字标签"

- 数字标签会把任务变成"读刻度 + 心算"，误差下降是必然的，但没有理论信息量；
- 只画 25/50/75 三条不标数字的刻度，保留了"估计"的成分，同时把角度/长度判断部分转成位置判断——这正是 C&M 层级里"位置优于角度"的操作化；
- 比例池刻意避开 25/50/75，避免刻度直接给出答案；刻度只提供参照点，仍需插值。

**混淆**：刻度也可能只是"锚点"，让被试把估计往 25/50/75 上靠。若数据出现"判断值在刻度附近堆积"，需要在讨论里指出。

---

## 4. 试次与平衡

- **Stroop 80 试次（2 块 × 40）**：每格 20 次，保证每格的标准误可控；块内一致/不一致严格 20/20，四种墨色各 10 次，避免颜色与一致性混淆。
- **区组顺序按编号哈希**：`U.hash(pid) % 2` 决定整合先还是分离先。n 很小时无法做到严格对半，但至少不是固定顺序；顺序写进每个试次（`block_order`），分析时可检查。
- **比例判断 40 试次**：2×2×10，四个条件完全交叉同一组比例值，避免"不同条件看到不同难度"的混淆；试次随机而非分块，减少策略切换。
- **练习**：Stroop 12 次、比例 4 次，都带反馈；练习数据用 `block_order='practice'` 标记，分析时剔除。

---

## 5. 计时与数据质量

- **试次流程**：3-2-1 准备 → 注视点 500 ms → 刺激（≤2000 ms，按键或超时结束）→ 空屏 500 ms + 0–100 ms 抖动 → 下一试次。练习与正式同一流程，只有练习带反馈。
- 为什么是这些数：四选一手动 Stroop 的正确 RT 中位数通常 600–900 ms，2000 ms 覆盖绝大多数正确反应；500 ms 注视足够把眼睛收回中央又不至于走神；空屏 500 ms 把相邻刺激分开，抖动避免按节奏预判。数值是计算机化范式的常见取值，不是某一篇论文的唯一规定；若实测 >1% 正确反应撞上限，收数前放宽到 2500 ms。
- 起点取 `requestAnimationFrame` 回调里的 `performance.now()`，而不是"设置 DOM 之后立刻"，把绘制延迟排除在 RT 之外；
- 按键监听只接受当次试次注册的键，忽略长按重复（`e.repeat`）；
- RT < 150 ms 记为抢按、> 2000 ms 记为超时，都不进入 RT 分析但保留在数据里，便于报告剔除率；
- 只允许电脑 + 键盘：设备检查要求窗口 ≥ 1000×620、四个键都通、被试自报能区分四色；手机打开会被拦住，避免触屏延迟与竖屏布局污染数据；
- 上传失败有本地备份（localStorage + JSON/CSV 下载）与重试，避免"做完才发现没传上去"。

## 6. 为什么坚持纯静态、`file://` 可运行

助教的自检方式是 clone 后双击 `index.html`。因此：

- 不用 ES module（`file://` 下会因 CORS 全部不执行），全部用传统 `<script src>` + IIFE；
- 不引 CDN（断网/被墙就白屏），字体用系统字体栈，图表手写 SVG；
- 不 fetch 本地文件（配置文件内联在 `js/config.js`）；
- 唯一的外部请求是收数接口，且已确认服务端开放 CORS。

代价是没有构建工具与依赖管理，代码只能靠 IIFE 命名空间约束；换来的是"双击就能跑"的确定性。

## 7. 结果页为什么坚持画个体点

n=5 时，均值柱状图会掩盖"效应只来自一个人"这种情况。因此每张柱状图都叠加个体点，并在文字里报告差值、dz、CI；ANOVA 表只作为辅助。这是小样本下更诚实的呈现方式。

## 8. 模型的选择

- **Stroop → EZ-DDM**：用正确率、平均 RT、RT 方差反解漂移率 v、边界 a、非决策时间 Ter，再模拟分布与实测比较。它把"更快/更慢"翻译成"证据积累效率与反应谨慎度"，比单纯报告均值多一层解释。
- **比例判断 → 周期幂模型**：`ĵ = p^β/(p^β+(1−p)^β)`，β 直接刻画"小比例高估、大比例低估"的偏差形状；刻度是否让 β 更接近 1，是可以直接读出来的。

两个模型都只做描述性拟合，不做模型比较或个体参数推断。

---

## 9. 界面设计的取舍

- **纸白 + 墨黑 + 铜色**：铜色只用于"改进条件"与强调，这样图表里哪个是原版、哪个是改进，不需要看图例就能分辨。
- **深色刺激舞台**：颜色词实验最怕背景色干扰；深底 + 高饱和四色对比稳定。界面是纸白的，刺激是深色的，两层分开，像一台安静的仪器。
- **少动效**：试次进行中零动画，只有页面切换的 180 ms 淡入；减少对计时与注意的干扰。
- **数字用等宽、表格用发丝线**：读数时对齐，视觉上不喧哗。

## 10. 按键与顺序的平衡（收数前补充）

被试在正式收数前先做了一遍，发现了两个会污染 RT 的顺序问题，都必须处理：

1. **区组顺序**：整合段先做与分离段先做不同（练习、疲劳、策略迁移）。处理：按编号哈希平衡；`block_order` 逐试次记录；分析时可把顺序当被试间变量做稳健性检查。
2. **按键顺序**：D/K 是中指，F/J 是食指。食指更省力、中指更易误按；同手连按只换手指，换手则要整只手切换，后者通常更慢。
   - 键位映射做成两套左右镜像（A：红 D/黄 F/蓝 J/绿 K；B：红 K/黄 J/蓝 F/绿 D），按编号哈希分配，让"手指难度"不固定绑在颜色上；
   - 每个区组 40 试次 = 39 次过渡，程序约束换手过渡落在 18–21 次（同手 18–21 次），让两种过渡大致各半；
   - `map / hand / finger / prev_key / hand_switch / pos` 全部写进数据，结果页给「顺序与按键：平衡检查」表。若同手/换手 RT 差异大，说明按键转换是重要协变量，Stroop 效应仍按条件内平均计算，并在讨论里报告这一检查。

这两类平衡都只能"减小并显式记录"，不能完全消除；n=5 时更不可能做到严格对半。写进局限。

## 11. 分离条件的可见性与注意（回答"会不会根本没看见灰字"）

- **可见性**：灰字 `#B0A795` 对 `#12100E`，对比度约 7.8:1，字号 104 px，位于注视点——它是可读的，不是隐形的。
- **真正的混淆**：分离条件下任务相关信息在色块上，灰字任务无关；被试可能"看见了但没加工字义"。这与"词和颜色不再同属一个客体"是两件事，本设计无法完全分离。
- **数据里的检查**：若灰字完全未被加工，分离条件的干扰应接近 0；若仍有可靠的正干扰（P2），说明语义信息至少被部分加工。因此分离条件的干扰及其 95% CI 本身就是结果的一部分。
- **更干净的对照（未做）**：第三种条件"高显著度分离词"（浅色/加轮廓），看干扰是否随词的可加工性回升；写进局限与反思。

---

## 12. 已知局限（写进 README）

1. 分离条件存在"词变灰 + 注意对象变化"的双重混淆，干扰下降不能单独归因于客体整合；
2. 顺序效应只能减小与记录，不能消除；n=5 时键位映射与区组顺序都无法严格对半；
3. 滑块初值固定 50，可能有轻微锚定；
4. n 很小，交互检验功效不足，结论只能算探索性；
5. EZ-DDM 用条件汇总矩反解，是近似拟合；
6. 逐试次按键与真实界面使用仍有距离，生态效度有限。
